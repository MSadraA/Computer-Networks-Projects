# تمرین کامپیوتری ۱ – بخش اول: UDP Pinger

این پوشه شامل دو برنامه‌ی `ping-server` و `ping-client` است. ارتباط بین آن‌ها با UDP انجام می‌شود و خود برنامه‌ها قالب پیام‌های `PING` و `PONG` را مدیریت می‌کنند.

## ساختار فایل‌ها

- `UDPSocket`: ایجاد سوکت و انجام عملیات ارسال و دریافت دیتاگرام‌ها.
- `MessageParser`: تبدیل پیام متنی به فیلدهای قابل استفاده و بررسی قالب آن.
- `PingServer`: دریافت درخواست‌ها، پاسخ دادن به درخواست معتبر و شبیه‌سازی اتلاف بسته.
- `PingClient`: ارسال پینگ‌ها، انتظار برای پاسخ و محاسبه‌ی RTT.
- `PingStats`: نگهداری و چاپ آمار نهایی.
- `main_server.cpp` و `main_client.cpp`: خواندن آرگومان‌های خط فرمان و اجرای برنامه‌ی مربوطه.

این تقسیم‌بندی باعث شده منطق شبکه، پردازش پیام و محاسبه‌ی آمار در یک فایل جمع نشوند؛ در عین حال برای هر قسمت کلاس جداگانه و غیرضروری هم اضافه نشده است.

## کامپایل

برای ساخت هر دو برنامه، در همین پوشه دستور زیر را اجرا کنید:

```bash
make
```

برای پاک کردن فایل‌های اجرایی:

```bash
make clean
```

فایل‌های اجرایی پس از کامپایل با نام‌های `ping-server` و `ping-client` ساخته می‌شوند. این فایل‌ها نباید در ZIP تحویلی قرار بگیرند؛ کافی است سورس‌ها و Makefile ارسال شوند.

## اجرای سرور

```bash
./ping-server --port P [--loss L] [--seed S]
```

- `--port`: پورت UDP سرور؛ اجباری و بین ۱ تا ۶۵۵۳۵.
- `--loss`: احتمال حذف هر درخواست معتبر، بین صفر و یک؛ مقدار پیش‌فرض `0.0` است.
- `--seed`: مقدار اولیه مولد اعداد تصادفی؛ در صورت ندادن این گزینه از زمان سیستم استفاده می‌شود. با تعیین Seed می‌توان نتیجه‌ی شبیه‌سازی اتلاف را تکرار کرد.

برای نمونه:

```bash
./ping-server --port 9000 --loss 0.2 --seed 123
```

## اجرای کلاینت

```bash
./ping-client --host H --port P [--count N] [--timeout MS] [--interval MS]
```

- `--host`: آدرس IPv4 سرور؛ مقدار پیش‌فرض `127.0.0.1` است.
- `--port`: پورت سرور؛ اجباری.
- `--count`: تعداد پینگ‌ها؛ مقدار پیش‌فرض `10` است.
- `--timeout`: حداکثر زمان انتظار برای پاسخ هر پینگ بر حسب میلی‌ثانیه؛ مقدار پیش‌فرض `1000` است.
- `--interval`: فاصله‌ی بین ارسال دو پینگ بر حسب میلی‌ثانیه؛ مقدار پیش‌فرض `0` است.

برای نمونه:

```bash
./ping-client --host 127.0.0.1 --port 9000 --count 5 --timeout 1000 --interval 200
```

## نکات مربوط به پروتکل

هر پیام باید حداکثر ۵۱۲ بایت باشد و قالب آن دقیقاً یکی از حالت‌های زیر باشد:

```text
PING <seq> <token>
PONG <seq> <token>
```

شماره‌ی توالی فقط از رقم‌های ده‌دهی تشکیل می‌شود و حداکثر ۱۰ رقم دارد. Token نیز باید بین ۱ تا ۶۴ نویسه‌ی ASCII چاپ‌پذیر داشته باشد. بین سه فیلد دقیقاً یک فاصله قرار می‌گیرد. وجود یک `\n` در انتهای پیام مجاز است.

سرور پیام نامعتبر را با `ERR BAD_REQUEST` پاسخ می‌دهد و برای آن احتمال اتلاف اعمال نمی‌کند. در مقابل، فقط درخواست `PING` معتبر وارد مرحله‌ی شبیه‌سازی اتلاف می‌شود.

کلاینت تنها پاسخی را قبول می‌کند که نوع آن `PONG` باشد و شماره‌ی توالی، Token، آدرس IP و پورت فرستنده با درخواست جاری و سرور مقصد مطابقت داشته باشند. پاسخ‌های نامرتبط یا دیررس تا پایان مهلت انتظار نادیده گرفته می‌شوند.

## چند سناریوی تست

### ۱. اجرای عادی

ابتدا سرور را اجرا کنید:

```bash
./ping-server --port 9000
```

سپس در ترمینال دیگری:

```bash
./ping-client --port 9000 --count 5
```

در حالت عادی باید برای هر پنج درخواست پاسخ دریافت شود و درصد اتلاف صفر باشد.

### ۲. اتلاف کامل بسته‌ها

سرور را با احتمال اتلاف یک اجرا کنید:

```bash
./ping-server --port 9000 --loss 1.0 --seed 10
```

و در ترمینال دیگر:

```bash
./ping-client --port 9000 --count 3 --timeout 500
```

هر سه درخواست باید Timeout شوند و در گزارش نهایی مقدار RTT به شکل زیر نمایش داده شود:

```text
rtt min/avg/max = -/-/- ms
```

### ۳. ارسال پیام نامعتبر

سرور را اجرا کنید و در ترمینال دیگری پیام نامعتبر بفرستید:

```bash
echo -n "INVALID 1 token" | nc -u -w1 127.0.0.1 9000
```

پاسخ مورد انتظار:

```text
ERR BAD_REQUEST
```

برای بررسی تعداد فیلدها نیز می‌توانید پیام زیر را بفرستید که باید نامعتبر شناخته شود:

```bash
echo -n "PING 1 token extra" | nc -u -w1 127.0.0.1 9000
```

### ۴. بررسی مقدارهای پیش‌فرض

سرور را بدون گزینه‌ی `--loss` اجرا کنید:

```bash
./ping-server --port 9000
```

در ترمینال دیگر نیز بدون تعیین `--interval` کلاینت را اجرا کنید:

```bash
./ping-client --port 9000 --count 3
```

در این حالت Loss پیش‌فرض سرور صفر و Interval پیش‌فرض کلاینت صفر است.

## ابزارهای استفاده‌شده

| ابزار | کاربرد |
|---|---|
| C++11 | پیاده‌سازی برنامه‌ها |
| UDP Socket API | ارسال و دریافت دیتاگرام‌ها |
| `select` | انتظار برای آماده شدن سوکت تا پایان مهلت تعیین‌شده |
| `std::chrono::steady_clock` | اندازه‌گیری زمان RTT و کنترل Timeout |
| Makefile | کامپایل و پاک کردن فایل‌های اجرایی |
| Tmux | اجرای هم‌زمان سرور و کلاینت در دو پنجره (اختیاری) |
| Netcat | فرستادن دستی پیام برای آزمایش رفتار سرور |

برای ساخت محیط دوپنجره‌ای Tmux، در صورت نصب بودن آن می‌توان از دستور زیر استفاده کرد:

```bash
make tmux-env
```

## استفاده از دستیار هوش مصنوعی

در این بخش از دستیار هوش مصنوعی برای راهنمایی درباره‌ی ساختار اولیه‌ی فایل‌ها، کار با `select` و تنظیم Makefile کمک گرفته شده است. اصلاحات نهایی و بررسی رفتار برنامه باید با اجرای تست‌ها و مرور کد انجام شود؛ مسئولیت توضیح و دفاع از تمام بخش‌های پیاده‌سازی نیز بر عهده‌ی اعضای گروه است.
