# UDP

<div dir="rtl">

پیاده‌سازی یک برنامه‌ی پینگ مبتنی بر پروتکل **UDP** شامل دو بخش کلاینت و سرور. تبادل پیام‌ها با قالب‌های `PING` و `PONG` انجام می‌شود و برنامه‌ها مسئولیت ارسال، دریافت، اعتبارسنجی و محاسبه‌ی آمار را بر عهده دارند.

</div>

---

## ساختار فایل‌ها

<div dir="rtl">

مسئولیت‌های پروژه به بخش‌های زیر تقسیم شده‌اند:

</div>

| بخش | مسئولیت |
|:---|:---|
| `UDPSocket` | ایجاد سوکت و ارسال و دریافت دیتاگرام‌ها |
| `MessageParser` | تبدیل پیام متنی به فیلدهای قابل استفاده و اعتبارسنجی قالب پیام |
| `PingServer` | دریافت درخواست‌ها، پاسخ به درخواست‌های معتبر و شبیه‌سازی اتلاف بسته |
| `PingClient` | ارسال درخواست‌های پینگ، انتظار برای پاسخ و محاسبه‌ی زمان رفت‌وبرگشت |
| `PingStats` | نگهداری و نمایش آمار نهایی |
| `main_server.cpp` و `main_client.cpp` | خواندن آرگومان‌های خط فرمان و اجرای برنامه‌ی مربوطه |

<div dir="rtl">

این تقسیم‌بندی، منطق شبکه، پردازش پیام و محاسبه‌ی آمار را از یکدیگر جدا می‌کند؛ بدون آن‌که کلاس‌های مستقل و غیرضروری به پروژه اضافه شوند.

</div>

## اجرای سرور

```bash
./ping-server --port P [--loss L] [--seed S]
```

<div dir="rtl">

**پارامترها**

- `--port` — شماره‌ی پورت UDP سرور؛ اجباری و در بازه‌ی ۱ تا ۶۵۵۳۵.
- `--loss` — احتمال حذف هر درخواست معتبر، بین صفر و یک. مقدار پیش‌فرض: `0.0`.
- `--seed` — مقدار اولیه‌ی مولد اعداد تصادفی. اگر مشخص نشود، از زمان سیستم استفاده می‌شود. تعیین این مقدار امکان تکرار نتیجه‌ی شبیه‌سازی اتلاف را فراهم می‌کند.

**نمونه‌ی اجرا**

</div>

```bash
./ping-server --port 9000 --loss 0.2 --seed 123
```

---

## اجرای کلاینت

```bash
./ping-client --host H --port P [--count N] [--timeout MS] [--interval MS]
```

<div dir="rtl">

**پارامترها**

- `--host` — آدرس IPv4 سرور. مقدار پیش‌فرض: `127.0.0.1`.
- `--port` — شماره‌ی پورت سرور؛ اجباری.
- `--count` — تعداد درخواست‌های پینگ. مقدار پیش‌فرض: `10`.
- `--timeout` — حداکثر زمان انتظار برای پاسخ هر درخواست، بر حسب میلی‌ثانیه. مقدار پیش‌فرض: `1000`.
- `--interval` — فاصله‌ی زمانی بین ارسال دو درخواست، بر حسب میلی‌ثانیه. مقدار پیش‌فرض: `0`.

**نمونه‌ی اجرا**

</div>

```bash
./ping-client --host 127.0.0.1 --port 9000 --count 5 --timeout 1000 --interval 200
```

## ساختار پروتکل

<div dir="rtl">

حداکثر اندازه‌ی هر پیام **۵۱۲ بایت** است. قالب پیام باید دقیقاً یکی از دو حالت زیر باشد:

</div>

```text
PING <seq> <token>
PONG <seq> <token>
```

<div dir="rtl">

**قوانین اعتبارسنجی پیام**

- شماره‌ی توالی فقط شامل ارقام ده‌دهی است و حداکثر ۱۰ رقم دارد.
- مقدار Token بین ۱ تا ۶۴ نویسه‌ی قابل چاپ از مجموعه‌ی ASCII است.
- بین هر دو فیلد دقیقاً یک فاصله قرار می‌گیرد.
- وجود یک نویسه‌ی خط جدید (`\n`) در انتهای پیام مجاز است.

**رفتار سرور**

در صورت دریافت پیام نامعتبر، سرور پاسخ `ERR BAD_REQUEST` ارسال می‌کند. برای این پیام‌ها احتمال اتلاف اعمال نمی‌شود؛ شبیه‌سازی اتلاف فقط برای درخواست‌های معتبر از نوع `PING` انجام می‌شود.

**اعتبارسنجی پاسخ در کلاینت**

کلاینت فقط پاسخی را معتبر می‌داند که نوع آن `PONG` باشد و مشخصات زیر با درخواست جاری مطابقت داشته باشند:

- شماره‌ی توالی پیام
- مقدار Token
- آدرس IP فرستنده
- شماره‌ی پورت فرستنده

پاسخ‌های نامرتبط یا دیررس تا پایان مهلت انتظار نادیده گرفته می‌شوند.

</div>

## سناریوهای تست

### ۱. اجرای عادی

<div dir="rtl">

ابتدا سرور را اجرا کنید:

</div>

```bash
./ping-server --port 9000
```

<div dir="rtl">

سپس در یک ترمینال دیگر، کلاینت را اجرا کنید:

</div>

```bash
./ping-client --port 9000 --count 5
```

<div dir="rtl">

در شرایط عادی باید برای هر پنج درخواست پاسخ دریافت شود و درصد اتلاف بسته‌ها صفر باشد.

</div>

### ۲. اتلاف کامل بسته‌ها

<div dir="rtl">

سرور را با احتمال اتلاف یک اجرا کنید:

</div>

```bash
./ping-server --port 9000 --loss 1.0 --seed 10
```

<div dir="rtl">

سپس در ترمینال دیگر کلاینت را اجرا کنید:

</div>

```bash
./ping-client --port 9000 --count 3 --timeout 500
```

<div dir="rtl">

هر سه درخواست باید با اتمام مهلت انتظار مواجه شوند. در گزارش نهایی، مقدارهای زمان رفت‌وبرگشت باید به شکل زیر نمایش داده شوند:

</div>

```text
rtt min/avg/max = -/-/- ms
```

### ۳. ارسال پیام نامعتبر

<div dir="rtl">

سرور را اجرا کنید. سپس در ترمینال دیگری، پیام نامعتبر زیر را برای آن بفرستید:

</div>

```bash
echo -n "INVALID 1 token" | nc -u -w1 127.0.0.1 9000
```

<div dir="rtl">

**پاسخ مورد انتظار:**

</div>

```text
ERR BAD_REQUEST
```

<div dir="rtl">

برای بررسی اعتبارسنجی تعداد فیلدها نیز پیام زیر را ارسال کنید. این پیام باید نامعتبر تشخیص داده شود:

</div>

```bash
echo -n "PING 1 token extra" | nc -u -w1 127.0.0.1 9000
```

### ۴. بررسی مقدارهای پیش‌فرض

<div dir="rtl">

سرور را بدون تعیین احتمال اتلاف اجرا کنید:

</div>

```bash
./ping-server --port 9000
```

<div dir="rtl">

سپس کلاینت را بدون تعیین فاصله‌ی زمانی بین درخواست‌ها اجرا کنید:

</div>

```bash
./ping-client --port 9000 --count 3
```

<div dir="rtl">

در این حالت، مقدار پیش‌فرض احتمال اتلاف در سرور صفر و مقدار پیش‌فرض فاصله‌ی زمانی در کلاینت نیز صفر است.

</div>

## ابزارهای استفاده‌شده

- **زبان برنامه‌نویسی:** `C++11`
- **ارتباط شبکه:** رابط برنامه‌نویسی سوکت‌های UDP
- **مدیریت انتظار سوکت:** تابع `select`
- **اندازه‌گیری زمان:** `std::chrono::steady_clock` برای محاسبه‌ی زمان رفت‌وبرگشت و کنترل مهلت انتظار
- **ساخت پروژه:** `Makefile` برای کامپایل و پاک کردن فایل‌های اجرایی
- **اجرای هم‌زمان:** `Tmux` برای اجرای سرور و کلاینت در دو پنل مجزا (اختیاری)
- **آزمایش دستی:** `Netcat` برای ارسال پیام و بررسی رفتار سرور

### اجرای محیط دوپنلی

<div dir="rtl">

در صورت نصب بودن ابزار `Tmux`، برای ایجاد محیطی شامل دو پنل و آزمایش هم‌زمان سرور و کلاینت، دستور زیر را اجرا کنید:

</div>

```bash
make tmux-env
```
